# Expo Go in the stores is SDK 57 only and Android Advanced Protection blocks the archived SDK 54 APK, so the phone app runs as a web page

Task attempted: run `apps/phone` (Expo SDK 54, RN 0.81.5) on the human's Android phone for the 2026-10-14 device run (LING-006), without an EAS build.
Steps:
  1. Install Expo Go from the Play Store, open `exp://192.168.1.122:8083` → Expo Go 57 refuses the SDK 54 project ("project is incompatible with this version of Expo Go").
  2. Find the per-SDK client: https://expo.dev/go lists "SDK 57 (latest)" only; `https://exp.host/--/api/v2/versions` gives `sdkVersions["54.0.0"].androidClientUrl` = https://github.com/expo/expo-go-releases/releases/download/Expo-Go-54.0.8/Expo-Go-54.0.8.apk (about 160 MB) and an `iosClientUrl` that is a simulator-only `.tar.gz` (about 30 minutes to find). Download the APK to the Mac, serve it on the LAN (`python3 -m http.server 8070`), open it in the phone's Chrome → Android **Advanced Protection** blocks "install unknown apps" for every source, with no per-app exception and no ADB route (developer options are hidden under Advanced Protection too).
  3. Fall back to the web: `npx expo install react-dom react-native-web @expo/metro-runtime`, restart the same Metro, open `http://192.168.1.122:8083/` in Chrome on the phone.
Expected: a store Expo Go that can open the SDK the project is pinned to (or a store that keeps the previous major), or a documented sideload path that survives Advanced Protection.
Actual: Expo Go in both stores tracks only the newest SDK; the archived APK exists but Advanced Protection makes it uninstallable; iPhone has no older-SDK path at all (no archived device client; only an EAS dev build, which needs the paid Apple Developer membership, decision 0011 pending). The web fallback needed two code guards: `crypto.randomUUID` is undefined on a LAN `http://` origin (secure contexts only), and the camera (`expo-camera`) needs https, so QR scanning is hidden on web.
Severity: Medium — about 60 minutes lost across the two dead ends; blocks any tester whose phone has Advanced Protection and any iPhone tester, i.e. the demo phone route for a project not on the newest SDK.
Workaround: run the phone app as a web page from the same Metro (`CI=1 EXPO_PUBLIC_API_URL=http://192.168.1.122:4000 npx expo start --port 8083 --lan`, open `http://<mac-lan-ip>:8083/`), typed code only; QR of the URL in the scratchpad.
Suggestion: Expo — keep the previous SDK's Expo Go in the stores for one release cycle, or show the exact fallback (web, EAS dev build) in the refusal screen. Lingo — keep the web build working (it is the only route for locked-down phones), and consider the SDK 57 upgrade (`npx expo install expo@^57 --fix`, after the freeze) or the EAS Android preview build (plan LING-006 M4) before the next device run; write the per-SDK Expo Go URL into apps/phone/README.md.
Environment: macOS 25.2 (Darwin), Expo SDK 54.0.0, Expo Go 57 (Play Store) / 54.0.8 (archived APK), Android phone with Advanced Protection, Chrome.
Links: https://docs.expo.dev/get-started/set-up-your-environment/ (Expo Go SDK pinning), https://expo.dev/go (archived APKs), https://exp.host/--/api/v2/versions (per-SDK client URLs), docs/plans/LING-006.md (Manual device steps M3–M5), docs/decisions/0011-phone-session-code-access.md, https://docs.expo.dev/workflow/web/ (web), https://developer.mozilla.org/en-US/docs/Web/API/Crypto/randomUUID (secure context), docs/spot-checks/2026-10-14-device-run.md rows 4a–4b.
