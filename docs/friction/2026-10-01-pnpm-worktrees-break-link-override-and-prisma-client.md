# pnpm worktrees break link override and prisma client

Task attempted: Run sub-agents in separate git worktrees (`.claude/worktrees/agent-*`, `../lingo-ling003`) so LING-001,
LING-002 and LING-003 can be built in parallel, each with its own `pnpm i`.
Steps:
  1. `git worktree add` a new checkout (e.g. `/Users/moizp/hackathon/lingo/.claude/worktrees/agent-…`).
  2. `pnpm i` in the worktree.
  3. Run tests / typecheck for `packages/pipeline`, `packages/shared-ui` and `apps/api`.
Expected: A worktree behaves like the main checkout after `pnpm i`.
Actual:
  - The root `package.json` has `"pnpm": { "overrides": { "@moizp/vega-media-kit": "link:../vega-media-kit" } }`. The
    `link:` path resolves relative to the worktree root, not the main checkout, so in a worktree it points at
    `<worktree>/../vega-media-kit`, which does not exist. Every import of `@moizp/vega-media-kit` (e.g.
    `packages/pipeline/src/vtt.ts`) is broken.
  - The Prisma client is not generated by a fresh install; `apps/api` tests and typecheck stop with
    `Cannot find module '.prisma/client/default'`.
Severity: Medium — hit by every new worktree, so every parallel sub-agent loses time on the same setup before its real task.
Workaround: After `pnpm i` in a worktree, re-point the kit link by hand (e.g. at the absolute path of the sibling repo
`/Users/moizp/hackathon/vega-media-kit`) and run `pnpm db:generate` (`prisma generate` in `apps/api`).
Suggestion: Project: use an absolute or env-driven path for the kit override (or publish the kit to a registry), and add a
`postinstall: prisma generate` to `apps/api`. pnpm: document that `link:` in `overrides` resolves from the workspace root, so
it breaks under git worktrees.
Environment: macOS 26.2, Node 22.19.0, pnpm 9.15.9, Prisma 6, git worktrees.
Links:
  - pnpm overrides: https://pnpm.io/package_json#pnpmoverrides
  - Prisma generate: https://www.prisma.io/docs/orm/prisma-client/setup-and-configuration/generating-prisma-client
  - Root `package.json` (`pnpm.overrides`), `apps/api/package.json`
