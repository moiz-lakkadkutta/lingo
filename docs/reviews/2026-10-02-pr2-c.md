## Medium

### M1 — `packages/pipeline/src/batch/plan.ts:138-160` with `run.ts:103-104`: a prepare run after a segment edit uses the old S3 cut when `upload` is not in the run, and it records the new segment, so later full runs skip prepare

- **Defect.** Prepare's own invalidation (`changed` → delete mezz/transcript/words/poster) assumes the S3 object at `sourceUriFor(c)` already
  holds the new cut. Nothing checks this. `planBatch` does not compare `_cuts/<slug>.uploaded` with `segmentKey(c)` before planning prepare.
  `runBatch` then writes `.segment.json` with the **new** key (`run.ts:104`) and the prepare marker with the new segment (`run.ts:113`),
  although prepare downloaded and transcribed the **old** cut. The poster has a guard for this case (`plan.ts:165`: "run the prepare stage
  first"); prepare has no matching guard for upload.
- **Scenario (reproduced with a probe against the real code).** The human runs a full draft, reviews the cues, moves the out-point, and
  re-runs `--stages prepare --only clip-1` (or `--stages cut,prepare`).
  1. Prepare runs with `reuse: undefined`. It calls Transcribe again on `s3://…/clips/clip-1.mp4`, which is still the old cut, because
     `.uploaded` still holds the old key.
  2. `.segment.json` and `.batch-draft.json` now say "new segment".
  3. The next full run plans `fetch:skip cut:run upload:run prepare:skip poster:run`. S3 gets the new cut, but `work/clip-1` (cues,
     highlights, VTTs, mezz) stays built from the old media. The report says `ok`.
  4. In `--phase final`, the published HLS and VTTs come from the old cut, with cue timings that do not match the new segment. One
     Transcribe charge is wasted, and nothing tells the human.
- **Fix.** For clips without `sourceS3`, block prepare when `fs.read(p.uploaded) !== key`, with a message such as "upload the new cut
  first (include the upload stage)". Alternatively, put the upload marker's content into prepare's `markerKey`, and write `.segment.json`
  only after prepare succeeds. Add a plan test: segment changed, stages `['prepare']`, a stale `.uploaded` → prepare is blocked.

## Low

- **L1 `run.ts:66-70`, `command.ts:256`.** The dry run over-reports Transcribe spend and shows steps that will not run. `transcribeLine`
  excludes a clip only when its *prepare* step is blocked. A manifest-problem block (on `steps[0]`) or an unconfirmed-cut block does not
  remove the clip. The dry run here lists `terra-x-so-trinken-baeume` (blocked at verify) and `jung-naiv-drogen` (cut BLOCKED) under
  "Transcribe will run for", and prints `[upload] run`, `[prepare] run (calls Amazon Transcribe)` after a BLOCKED cut. The runner stops
  at the block (`run.ts:128` `break`). Fix: a clip whose earlier step is blocked shows `not reached` for later steps and is left out of
  the Transcribe line and the estimate.
- **L2 `plan.ts:131`.** `segment.confirmed: false` only stops the *cut*. Once the cut exists (from the runbook's `--allow-unconfirmed`
  step), a run without the flag uploads, transcribes and, in `--phase final`, publishes the unconfirmed segment. The report then lists it
  under "Needs a human" after the fact. Fix: block `upload`/`prepare` for unconfirmed rows unless `--allow-unconfirmed`, or at least in
  the final phase.
- **L3 `plan.ts:128-132`.** The cut writes directly to `_cuts/<slug>.mp4`, with no `.part` file as fetch has. Following the runbook ("delete
  that cut, re-run") without changing the segment leaves `<slug>.cut.json` matching. A Ctrl-C during ffmpeg then leaves a partial cut that
  the next run skips and uploads. Fix: cut to `.part` and rename after the probe, or remove the cut marker before cutting.
- **L4 `plan.ts:162-171`.** The poster and its upload are not keyed. Changing `posterAtS` does not re-make `poster.jpg`, which is skipped
  while it exists. `.poster-published` holds a timestamp, so a re-made poster is not re-uploaded. Fix: key both on `{posterAtS, segment}`.
- **L5 `run.ts:126`.** A blocked step goes through the same `catch` that deletes `step.output`. With `--stages cut` (or `poster`) and a
  manifest problem, the problem block lands on that step with `skip` removed (`plan.ts:173-177`), and the existing good cut or poster is
  deleted. Fix: delete output only when the step actually ran.
- **L6 `command.ts:222, 227`.** The manifest path resolves against `INIT_CWD` (where the human typed it), but `--work` and `--report`
  resolve against the pnpm package cwd (`packages/pipeline`). `--report content/batch` therefore writes
  `packages/pipeline/content/batch.{json,md}`. Fix: resolve both like the manifest, or document it in `--help`.
- **L7 `packages/pipeline/src/highlights.ts:34`.** The merged number-word rule (M5) treats the common verb *achten* ("achten auf") and
  *Achte* as ordinals. They are never highlighted (`isNumeral('achten') === true`, checked with tsx). Fix: drop `en` from the irregular
  ordinal endings for `acht`, or accept the loss. "second" (as in "wait a second") is also never highlighted, which may be intended.
- **L8 `apps/phone/src/screens/QuizScreen.tsx:60-70`.** After a lost answer, the retry reuses the word's `reviewId` even when the learner taps
  a *different* grade. The server keeps the first grade (`me.ts:77` returns the stored schedule), while the client applies the second
  locally (re-queue and first-pass tally). Fix: key the id on `savedWordId` + grade, or lock the grade after the first attempt and offer
  only "Try again".
- **L9 `TASKS.md:5, 7, 23, 39`.** Lines 5 and 7 say `0009-gloss-quality.md` and `LING-002-gate-c.md` are "on `origin/feat/ling-001-pipeline`,

  `prepare.ts:48-52, 166` publishes nothing when `publish === false`. `--publish` without `--force-ai` is ignored with a message.
- **No double Transcribe.** `reuse` (`plan.ts:142`) and `transcribes()` (`estimate.ts:187`) use the same rule (`!cues && !changed &&
  transcript.json exists`). Prepare reuses the transcript and re-normalises a missing mezz (`prepare.ts:64-80`). A quality-gate failure
  leaves `transcript.json`, so the re-run reuses it. Exception: M1.

  `.segment.json` invalidating mezz, transcript, words, poster and the poster marker. A `cues` clip whose segment changed is blocked with
  re-timing instructions.
