## Medium

### M1: Leaving the Player for the Plus screen and pressing Back restarts the clip from the beginning (or the old resume point), and the position is never saved
- `packages/shared-ui/src/app/Root.tsx:238`: `onPlus={() => nav({ type: 'push', route: { name: 'plus' } })}` on the Player route.
- `Root.tsx:134`: only the top route is mounted. `Root.tsx:207-209`: `PlayerRoute` remounts from `clips.fresh(slug)`, whose `resumeS` is the value fetched
  before the visit.
- `screens/Player.tsx:65,161`: `initialState(clip.resumeS ?? 0)` and `startAt={clip.resumeS ?? 0}`.
- **Defect:** the Explain card sends the learner to Plus in two places: the save-limit CTA (`Explain.tsx:51`, "Get Lingo Plus" after
  the 20th word) and, through the same `onPlus`, any upsell. The push unmounts the Player without calling `onBack(position)`. Nothing writes
  the playhead to the server or to the clip cache. When Plus pops, the Player mounts again and autoplays from the stale `resumeS`.
  For a clip started fresh, that is 0:00.
- **Scenario:** a free learner is 4 minutes into a clip and saves the 21st word. They press "Get Lingo Plus" and either buy or press Back.
  The clip restarts at 0:00. `PUT /me/progress` was never sent, so Continue doesn't have the position either. This is the
  money path: the learner who just paid is the one who gets sent back to the start.
- **Evidence (probe):** boot → hero Watch → `player.props.onPlus()` → Plus screen shown → Back.
  The output was `P1 first resumeS null`, `P1 after back resumeS null progress calls 0`.
- **Fix:** before the push, save the position the same way Back does. Either (a) give `Player` an `onLeave(positionS)` that Explain's
  `onPlus` goes through, so Root writes `clips.set(slug, cc, { ...clip, resumeS: pos })` plus a fire-and-forget `putProgress`
  and then pushes `plus`; or (b) keep the playhead in Root (`ctx.lastPosition[slug]`) and pass it as `startAt`. Add a Root test:
  `onPlus` at 240 s, then Back, should remount the Player with `resumeS` 240.

### M2: On Vega, Select on a Words row or "Replay the line" in the TV quiz still mounts KitPlayer and crashes the app
- `packages/shared-ui/src/components/MiniPlayer.tsx:20` mounts `KitPlayer` without checking caps. It is used by `screens/Words.tsx:123-126` and `screens/Quiz.tsx` (replay).
- `apps/vega/metro.config.js:45`: on Vega, `shaka-player` resolves to an empty module. The kit's Vega adapter then does
  `new shaka.Player()` in an effect (`vega-media-kit/src/player/adapters/vega.tsx:18,26`), and `shaka.Player` is undefined, so it throws a TypeError.
  On top of that, the adapter renders the w3cmedia `VideoPlayer` class as a component (KIT-010).
- **Defect:** the LING-008 M4 fix put the `caps.playback === false` guard in the Player only (`Player.tsx:37`). Decision 0013
  §Consequences says "A demo on Vega shows the playback message, never a crash", but the integrated app has two more ways to reach the
  stub. TASKS.md:52 tracks this as a follow-up, but nothing stops it in this PR, and both paths are one Select from a main screen.
- **Scenario:** on the VVD, Home → rail Words → Select on any saved word, and the app throws. Or: finish a clip on the Fire TV, then
  try the TV quiz on Vega (Summary → Quiz on TV → a cloze item → "Replay the line"), and the app throws.
- **Fix:** guard in one place. `MiniPlayer` takes `caps?: Caps` (default `platformCaps`). When `playback === false`, it renders a
  `T` with `strings.playbackOff.title` in the 640×360 box and calls `onEnd` on mount, so Quiz's `replayEnd` still fires. Add a render test
  for both callers with `caps.playback: false`, as `player.test.tsx` already does for the Player.

## Low

**L1. The Vega-safe import rule for shared-ui is a deny-list, not the supported list.** `packages/shared-ui/eslint.config.js:16-19`.
CLAUDE.md says "no native imports outside the Vega-supported list". The lint blocks named packages, such as `react-native-iap`, `@amazon-devices/*`
and `@react-native-async-storage/*`, so any other native package passes (`react-native-reanimated`, `expo-crypto`, `react-native-mmkv`).
Today's imports are fine: `react`, `react-native`, `react-native-svg`, `socket.io-client`, `qrcode-generator`, `@lingo/contracts` and the
kit. Fix: make it an allowlist, as `scripts/check-vega.mjs` `ALLOWED_IMPORTS` already does for apps/vega, either with a small node
check over `packages/shared-ui/src` or with `no-restricted-imports` patterns `['*', '!react', '!react-native', ...]`.

**L2. Alexa "stop" (transport `stop`) does nothing in the Player.** `platform/transport.ts:63` maps `stop` to the key `'back'`, and
`usePlatformMedia.ts:24` feeds it to the machine as `{ type: 'key', key: 'back' }`. `screens/player/machine.ts` handles Back only as
the event `{ type: 'back' }`. Every phase's `'key'` branch ignores the key `'back'` (e.g. `machine.ts:125-133`). `test/transport.test.ts:10`
checks only the mapping. Today this is dormant, because the kit's media controls are no-ops (KIT-E4). Fix: in `usePlatformMedia`, route `stop` to the
machine's `back` event (pass a separate `onStop` callback), and add a test that `stop` exits.

**L3. On Vega, every Watch writes a progress row and puts the clip on Continue.** `Player.tsx:37` calls `props.onBack(clip.resumeS ?? 0)` from
`PlaybackOff`. `Root.tsx:240-245` then sends `PUT /me/progress { positionS: 0, completed: false }` and caches `resumeS: 0`. So opening any clip
on Vega, where nothing can play, makes it "Continue watching" at 0:00. Fix: give `PlaybackOff` a plain `onLeave` that pops without
writing progress. Alternatively, skip the PUT in Root when `pos === (clip.resumeS ?? 0)`.

**L4. Back on the offline screen pops a stack the learner cannot see. Retry then throws the stack away.** `Root.tsx:93-96`, `:124-126`, `:83`.
`useSession`'s `onOffline` (`Root.tsx:89`) can turn a running app into the full-screen offline message, and the nav stack stays underneath. Back
calls `canPop` → `pop` while the offline view stays put, so the learner presses Back several times and nothing changes. Retry re-runs boot,
and that `reset`s to Home or First run, even when a Content Launcher intent had just opened a Player. Fix: while `boot !== 'ready'`, have the
listener return false (the OS leaves) or ignore Back. On a re-boot after the first one, keep the stack unless `firstRunDone` changed.

**L5. A launch intent over a running Player drops the old clip's position and saved words.** `Root.tsx:116` pushes
`player:<B>` over `player:<A>`. A's `onBack` is never called, so no progress is saved, and `PlayerRoute`'s effect (`Root.tsx:211-213`) clears `saved`.
Back returns to A at its old `resumeS` with an empty saved list, so its Summary says "You watched the whole clip…". Fix: when the top
route is a player, `replace` instead of `push` after saving A's position (same mechanism as M1). Alternatively, ignore intents while a Player is open.

**L6. `check:vega` compares names only, so the Vega declaration can drift in shape.** `scripts/check-vega.mjs:124-130` with
`apps/vega/types/lingo-shared-ui.d.ts`. The d.ts matches today: RootProps, PlusStore, IdStore, the mappers and LaunchIntent all agree. But a new
required `RootProps` field, or a changed mapper signature, still passes both `check:vega` and `tsc` in apps/vega, and only shows up at
runtime. Fix: in the shared-ui package (which has both type sets), add a type-level test, e.g. a `test/vegaDecl.test-d.ts` that imports the
d.ts types under an alias and asserts `RootProps` assignability both ways. Alternatively, generate the d.ts with `tsc --emitDeclarationOnly` for those exports.

**L7. Several focusables are labelled "Back", "Done", "Continue" or "Try again" rather than their purpose.** `strings.common.back` is used as the aria-label in
`About.tsx:27`, `Clip.tsx:38`, `Quiz.tsx:49` and `Root.tsx:217,264,281`. `Quiz.tsx:61` is "Done" (`strings.quiz.finish`), `Quiz.tsx:102` is "Continue",
and the StateMessage retry actions are "Try again". The Plus and PlaybackOff screens already use "Back to the previous screen", so the
convention exists. Fix: add purpose labels, e.g. "Back to the previous screen", "Leave the quiz and go back to the summary", "Next question",
"Try loading again".

**L8. Plus: an `invalid` verify after a purchase shows the "pending" promise, which nothing will keep.** `plus/machine.ts:305`. Any
`verified` result with `plus: false`, `invalid` included (RVS 400/497 or the wrong SKU), becomes `back('pending')`: "We'll finish setting up
Lingo Plus the next time you open Lingo". The startup restore will get `invalid` again every time. Subscribe also stays hidden for the
rest of the visit. Fix: send `outcome === 'invalid'` to `back('retry')`, or to a separate note telling the learner to contact Amazon, and keep `pending` for
`unavailable` and `verifyError`.

**L9. Plus "busy": the comment says focus parks on a view that cannot take focus.** `screens/Plus.tsx:109-110`. `View focusable={false}`
cannot hold focus. The focused Subscribe or Restore unmounts, so focus is lost. On Vega, the next D-pad press may do nothing until the
phase changes. It does recover, because the new buttons mount with `hasTVPreferredFocus`. Fix: correct the comment. Or keep the
Back button in the busy phase (Back already works there), which also gives VoiceView something to read.

**L10. `lint:words` doesn't cover the platform entries.** `scripts/lint-words.mjs:5` checks only `packages/shared-ui/src` and `apps/phone/src`.
`apps/vega/src` and `apps/expo` have no learner-facing copy today: their strings are console logs and Amazon response codes. But the
`// lint-words-allow` in `apps/vega/types/lingo-shared-ui.d.ts:25` suggests someone expected it to run there. Fix: add
`apps/vega/src/**` and `apps/expo/{*.tsx,src/**}` to the globs. Nothing should fail today.

## Checked and fine
- **Root navigation and Back.** There is one Root listener, registered first. Screen listeners (Player, PlaybackOff, Plus, Words mini player, First run) are
  added later and run first. First run's panel 1 returns false, so the OS leaves the app. `RouteView` is keyed by `stack.length:routeKey`, so a replace
  (player → summary) remounts the route, and a Words filter replace does not. Quiz → Again (pop + replace) and Next behave as intended.
- **Focus memory.** Home, Clip, Words (per filter, review 005 M4) and Settings remember focus. Plus and Pair don't need it. Returning from Plus to the
  rail or to Settings lands on `rail:plus` and `row:plus`. Clip keeps the same `challenge` id whether or not the learner has Plus.
- **Launch intents.** The cold start is queued: `createLaunchBus` holds one pending intent before Root mounts, and `useLaunchIntents` holds it until the catalog loads.
  Unknown slugs are ignored. A push of the route already on top is a no-op.
- **Player.** `caps.playback === false` → `PlaybackOff` (review 008 M4 fixed). Challenge is gated in Root
  (`challenge && learner.plus`), and Clip routes free learners to Plus. 0.75× is gated in the machine (`slower`: `caps.rate && plus`) and in the
  sheet (the upsell line). On Vega `caps.rate` is false, so the Speed row and the Explain "Slower" button are hidden.
- **The M3 dead-screen fix.** Paused before the first line, the stage stays focusable (same `stageKey`) and is labelled "paused". Select or Play resumes,
  and the stage remounts by `stageKey`. Select before the first line while playing only shows the chrome.
- **The Plus machine.** The transitions match the LING-007 review fixes: verify failure → pending, restore error vs empty, unavailable receipts,
  and resume to active. A second purchase is never invited.
- **Device id.** Fire OS uses AsyncStorage and `expo-crypto` `randomUUID`; Vega uses MMKV `{ id: 'lingo' }` and `randomUuid`. Both stores are module-level
  constants, so `useDeviceId`'s effect runs once. Root renders only after the id is known. `RootProps.deviceId` is required, and the
  root test checks the header.
- **The expo App.tsx wiring.** `plusStore`, `launchBus` and `remoteBus` are module-level. LaunchBridge emits before Root mounts, and the bus queues the
  intent. The Root props match.
- **The Vega project.** The manifest and app.json component id agree, and so do the 0.83 track, the IAP lib (~2.13.0, not 2.12.13), and the needs.module entries
  and interface provider for the IAP and the Content Launcher. Every `@amazon-devices/*` import is a dependency, and the d.ts names match
  `index.tsx`. `tsc` is clean against the real Vega type packages.
- **Tokens.** No colour literal outside `tokens.ts`.
- **Focus treatment.** Every focusable goes through `Focusable` (outline plus the 1.04 scale in 150 ms) or `WordChip` (decision 0006 B), apart from
  the invisible Player stage. Every focusable has an aria-label; L7 lists the ones that don't state a purpose.
