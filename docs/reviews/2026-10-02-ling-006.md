## Medium

### M1. The session code is a permanent, unthrottled bearer credential with full read and write access to the TV learner
- **Where:** `apps/api/src/lib/learner.ts:13-19`; `apps/api/src/routes/sessions.ts:12-14` (latest session reused forever); `apps/api/src/routes/me.ts:15-16` (GET/PUT `/me` now accept the code).
- **Defect:** any client that sends `x-session-code` becomes the TV's learner on every `/me/*` route, including `PUT /me` (changes the TV's learning language, native language, cue scale and so on) and `POST /me/words` / `POST /me/reviews` (changes the schedule). Codes never expire or rotate. The code space is 32⁶ ≈ 1.07×10⁹. Nothing is rate-limited on HTTP or on socket `join`. The answers differ by case: 400 for a malformed code without a DB hit, 404 `UNKNOWN_CODE` for a well-formed unknown code, 200 for a hit. That makes `/me` a clean oracle.
- **Failure scenario (probe, review_006):** `PUT /me` with `x-session-code: <TV code>` and body `{learning:"en"}` returned 200, and the TV learner's `learning` became `en`. On enumeration: at about 2,000 req/s against an API with 1,000 TVs, one guess in about 1.07M hits, so the expected time to the first hit is about 9 minutes. A phone that paired once (for example a guest's phone) keeps access forever, because "Use another TV" is client-side only.
- **Context:** plan R4 accepts this for the hackathon. Today the API runs only on the LAN (infra has no API stack). It must not reach an internet-facing deployment as is.
- **Fix:** (a) Scope the code to what the phone needs. Allow `GET /me`, `GET /me/words`, `POST /me/reviews` and `GET /me/stats`; reject `PUT /me` (and `PUT /me/level` and `/me/progress` from LING-005) with 403 when the identity came from `x-session-code`. One way: `learner(req, { allowCode: boolean })`, or return `{ learner, via: 'code' | 'device' }`. (b) Add an IP rate limit on `UNKNOWN_CODE` answers, both on `/me/*` and on socket `join` (for example `express-rate-limit` keyed by IP, 20 misses/min). (c) Record the follow-up in decision 0009 / feature-requests: rotate the code on "Pair a new phone", or have `join` issue a per-phone token.

### M2. `GET /me` with a session code leaks the TV's `deviceId`, a second credential that outlives the code
- **Where:** `apps/api/src/routes/me.ts:15`: `ok(res, await learner(req))` returns the raw Prisma `Learner`.
- **Defect:** before this diff the caller only ever saw its own `deviceId`. Now a code holder gets the TV's `deviceId`. That value works as `x-device-id` on every `/me/*` route, and `POST /sessions` with it returns the TV's current code. Rotating or revoking the code later (the M1 fix) would therefore not lock the holder out.
- **Failure scenario (probe, review_006):** `GET /me` with `x-session-code` returned `deviceId = review-probe-tv-…`. `POST /sessions` with `x-device-id: <that>` returned the same code (`PMYBYG`), so the session was recovered.
- **Fix:** `ok(res, LearnerDto.parse(await learner(req)))` (Zod strips unknown keys; the phone already parses `LearnerDto`). Do the same in `PUT /`. Add a test: GET `/me` via the code has no `deviceId`, `id` or `knownRank`.

### M3. pino-http writes `x-session-code` (and `x-device-id`) to the log on every request
- **Where:** `apps/api/src/app.ts:19`, `app.use(pinoHttp({ logger }))`. This becomes load-bearing because of `learner.ts:13`, which makes the header a credential.
- **Defect:** pino-http's default request serializer includes all request headers.
- **Failure scenario (reproduced):** `GET /me` with `x-session-code: ABCDEF` logged `"req":{"headers":{"x-session-code":"ABCDEF","x-device-id":"tv-1",…}}`. The API test run also prints full headers. Anyone who can read the logs (CloudWatch, a shared terminal, a pasted bug report or friction log) gets working credentials for every active TV.
- **Fix:** `pinoHttp({ logger, redact: { paths: ['req.headers["x-session-code"]', 'req.headers["x-device-id"]'], censor: '[redacted]' } })`. Add a test that captures the log stream and asserts the code is absent.

### M4. Any `session:error` after a reconnect makes the phone forget the TV permanently
- **Where:** `apps/phone/src/lib/link.ts:35-38` (`if (joined && e.code !== 'UNKNOWN_CODE') return; close(); h.onRefused(e)`) and `apps/phone/src/App.tsx:43,46` (`onRefused` → `refused()` → `store.forgetTv()` plus the `unknownCode` hint).
- **Defect:** the `disconnect` handler sets `joined = false`. After socket.io auto-reconnects and re-emits `join`, any `session:error` is treated as a refusal, including `INTERNAL` (the server's `guard` sends it whenever the join handler throws, for example on a Prisma or Postgres hiccup during an API restart) and `VALIDATION`. The phone then deletes the remembered TV, closes the socket (so no further retries) and shows "No TV with that code", which is not true. The same happens on first boot if the API comes up before Postgres is ready.
- **Failure scenario (probe against the real `createPhoneLink` with a fake socket):** `connect → phone:connected → disconnect → connect → session:error{INTERNAL}` produced the handler log `transport:true | joined | transport:false | transport:true | refused:INTERNAL`. In App that becomes `forgetTv()`, so the user has to re-pair after a server blip (manual step D14 restarts the server and would hit this when the DB is slow).
- **Fix:** in link.ts, call `onRefused` only for `UNKNOWN_CODE` (and `VALIDATION` only while a join is in flight on first connect). For `INTERNAL`, keep the socket and re-emit `join` after a backoff (or `s.disconnect().connect()`), and call `onTransport(false)` so the UI shows "Reconnecting…". Add a `link.test.ts` case: INTERNAL after a reconnect does not call `onRefused`.

### M5. `POST /me/reviews` is not idempotent, so a retry after a lost response applies SM-2 twice
- **Where:** `apps/api/src/routes/me.ts:59-64` (read-modify-write with no version guard); `apps/phone/src/screens/QuizScreen.tsx:60` (any failure → `gradeFail` → "That didn't reach Lingo. Try again." → the user re-grades).
- **Defect:** if the server commits but the response is lost (Wi-Fi drop, app backgrounded, proxy reset), the phone reports `NETWORK` and invites a retry. The retry reads the already-updated row and advances it again. Two concurrent submits (a double tap that slips past the `deck.posting` closure check) race in the same way and both write.
- **Failure scenario:** the user grades a new word "Good" and the response drops, so the word now has reps 1 and interval 1. The user taps "Good" again and the server moves it to reps 2, interval 6 (the existing test "a second good schedules it 6 days out" shows exactly this transition). There are two `Review` rows, and the word skips its 1-day review, so the schedule is silently corrupted.
- **Fix:** add a client-generated review id (`ReviewPost.reviewId: uuid`, unique on `Review`). On a duplicate, return the current `ReviewResult` without re-applying. Or make the update conditional: `db.savedWord.updateMany({ where: { id, reps: w.reps, lapses: w.lapses, intervalD: w.intervalD }, data })`; if `count === 0`, return the current state with 200 and the phone treats it as `gradeOk`. Add an API test: the same `reviewId` posted twice gives one Review row and interval 1.

### M6. Screen-reader users cannot reach the meaning: label overrides hide the gloss, example and cue, and the quiz "Hear it" button is swallowed
- **Where:** `apps/phone/src/components/WordChip.tsx:13-24`; `apps/phone/src/screens/QuizScreen.tsx:109-117`.
- **Defect:** (a) The chip is a `Pressable` with `aria-label = "<word>. Show the meaning and hear it"`, and the gloss and example are rendered *inside* it. An explicit label replaces the children, so when the chip is open TalkBack and VoiceOver still read only the word and "Show the meaning". The meaning, the chip's whole purpose, is never announced. (b) The quiz back card is `<View accessible aria-label="word: gloss">`. `accessible` groups the subtree into one element, so the cue line, the native line and, on iOS, the nested "Hear it" `Button` are not reachable with VoiceOver. That breaks CLAUDE.md's "every focusable has an aria-label stating purpose" for that button.
- **Failure scenario:** with VoiceOver on, a learner opens a chip and hears "Bahnhof. Show the meaning and hear it" plus the TTS word, but never "station" or the example. On the quiz back, swiping lands only on "Bahnhof: station", skips the cue sentence and cannot reach "Hear it". Manual step D16 would surface this, but no automated test covers the case.
- **Fix:** (a) Render gloss and example as siblings *after* the Pressable (they are already in the wrapping `View`), or make the label state-aware: `open ? \`${w.word}: ${w.gloss}. ${w.example}. Hide the meaning\` : chipLabel(w.word)`. (b) Drop `accessible` on the back-card `View` (let each `Text` and the button be its own element), or keep a grouped label that includes `cueText` and `cueNative` and move the Hear button outside the grouped view. Add a screens test asserting the open chip's label (or a sibling text) contains the gloss, and that no `accessible` ancestor wraps a `Pressable`.

## Low

- **L1. Quiz events do not check the sender's role.** `apps/api/src/sockets.ts:45-57`. A phone can emit `quiz:start` (other phones get "Quiz me now") and a TV can emit `quiz:result`. Fix: `if (socket.data.role !== 'tv')` for start and `!== 'phone'` for result → `session:error VALIDATION`. Add one test each.
- **L2. Stale room membership** (`join` handler, outside this ticket). `socket.join(code)` never leaves a previous room, so a socket that re-joins with another code still receives the old room's `quiz:*` and `word:saved` while `socket.data.code` names the new one. The phone uses a fresh socket per join, so it is not affected; the TV might be. Fix in the owner's ticket: `for (const r of socket.rooms) if (r !== socket.id) socket.leave(r)` before joining.
- **L3. Backspace on a filled code box may re-insert the character.** `apps/phone/src/components/CodeBoxes.tsx:34-45`. RN fires `onKeyPress` (Backspace) and then `onChangeText('')`. If both run against the same `boxes` closure, `typeInto(boxes, i, '')` returns the stale boxes and `onBoxes` restores the cleared character. Not provable without a device; check in D2. Fix: in `onChangeText`, treat `text === ''` as a no-op (Backspace is handled in `onKeyPress`).
- **L4. ATS keys conflict.** `apps/phone/app.json:15-16`. On iOS 10+, `NSAllowsArbitraryLoads` is ignored when `NSAllowsLocalNetworking` is present (Apple, NSAppTransportSecurity docs). LAN IPs and `.local` names still work; a plain-HTTP hostname would not. Keep one key deliberately and verify in M5.
- **L5. Streak edge cases.** `me.ts:38`: re-saving an already-saved word (upsert no-op) counts as a study day. In addition, `Learner.streak` (exposed raw in `LearnerDto`) keeps the old count after a missed day until the next activity. LING-005 must read `/me/stats.streak` (`displayStreak`), not `LearnerDto.streak`, or the TV will say "Day 6" while the phone says "Welcome back". Add this to the LING-005 handshake.
- **L6. No fetch timeout.** `apps/phone/src/lib/api.ts:25`. A hung request leaves the grade buttons disabled (`posting`) and the spinner up indefinitely on some Android stacks. Fix: `AbortController` with about 15 s, mapped to `ApiError(0,'NETWORK')`.
- **L7. An unknown code from a deep link or QR forgets the remembered TV.** `App.tsx:43,62-66`: `join(B)` → refused → `store.forgetTv()` clears TV A as well. Fix: clear storage only when the refused code equals the stored one; otherwise rejoin A.
- **L8. Leaving Review mid-deck drops same-session repeats.** `QuizScreen.tsx:37-45`: switching tabs unmounts the deck. "Again" words were already posted (now due tomorrow), so the local repeats are lost. Acceptable; either keep the deck in App state or note it.
- **L9. EAS reproducibility.** `apps/phone/package.json` scripts use `npx eas-cli@latest`; pin a major (for example `eas-cli@16`) to match `cli.version >= 16.0.0`. The pre-install stub path (`ROOT/../vega-media-kit`) matches the plan and is unverified until M4 (R2). The EAS builder also installs the whole workspace (apps/vega, apps/expo with react-native-tvos), so expect a slow install or a failure there; capture it in a friction log.
