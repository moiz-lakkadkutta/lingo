## High

### H1 — Every TV is the same learner (`dev-device`). Server-side ownership checks protect nothing between real devices, and one purchase gives Plus to everyone
- `packages/shared-ui/src/app/Root.tsx:57`: `deviceId = 'dev-device'` is the default.
- `apps/expo/App.tsx:17` and `apps/vega/App.template.tsx:29`: neither entry passes `deviceId`.
- `apps/api/src/routes/sessions.ts:12-17`: `getOrCreateSession` reuses the learner's latest session.
- **Defect:** every Fire TV and every Vega device sends `x-device-id: dev-device`. The server's per-learner checks on `/me/progress`, `/me/level`, `/me/library`, `/me/words`, `/iap/*` work as written, but all TVs map to one learner. That learner shares:
  - `firstRunDone`, level, progress (Continue row), library and SM-2 state;
  - the Plus entitlement, since `entitled(learnerId)` counts Purchase rows per learner;
  - the session code. POST /sessions is idempotent per learner, so every TV shows the same 6-character code and every phone joins one room.

  The default existed before LING-005. The integration makes it carry real weight: LING-007's Plus and restore-on-startup are now wired through Root (d4f1c48), and LING-005 added level, progress and library per learner.
- **Scenario:** household A buys Lingo Plus on its stick. Household B's stick, on the same API, gets Challenge mode and 0.75× on its next `/me`. B's quiz scores move A's level. A's saved words show on B's Words screen. B's phone "Quiz on your phone" lands in A's room (`quiz:start` to the shared code), and A's `word:saved` events show up on B's phone.
- **Fix:**
  1. Create a stable per-install id in each platform entry and pass it as `deviceId`. MMKV is on the Vega supported list; expo can use expo-application / SecureStore, e.g. `tv-${uuid}` created once.
  2. Make `deviceId` required in `RootProps`, or have Root throw when it is missing outside tests, so a shared constant can never ship.
  3. Add a root test asserting the entries pass an id. Add a manual checklist step: two devices show different pairing codes.

## Medium

### M1 — `PUT /me/level` trusts the caller's quiz score, accepts unpublished clips, and since the merge accepts any `x-session-code` holder (the phone)
- `apps/api/src/routes/learning.ts:26-42`: notably 34-39.
- `apps/api/src/lib/learner.ts:12-20`: the session code wins over the device id.
- Merge d4f1c48 replaced the plan's device-id-only `tvLearner` (`lib/learnerLookup.ts`, deleted) with the shared `learner(req)`.
- **Defect:**
  - (a) `total` comes from the client and is never compared with the clip's `QuizItem` count. The "≥ 5 items" eligibility (`MIN_ITEMS`) and "≥ 90 %" are therefore whatever the client says.
  - (b) Only an unknown slug is a 404. A draft clip, or a clip with zero quiz items, is accepted.
  - (c) The plan (§0.8, Open question 3) keeps the phone's quiz out of the level rule. The merge routes x-session-code callers to the TV learner on these TV-only routes, so a phone, or anyone holding the non-expiring 6-character code, can post `source: 'quiz'` or `source: 'settings'` for the TV. The exclusion now rests only on a code comment in `sockets.ts:44`. `PUT /me/progress` (`learning.ts:14-23`) also accepts drafts and session-code callers.
- **Scenario:** the probe (`scratchpad/probe/level.mts`) creates an A2 learner with a session, then two **draft** A2 clips with **0 quiz items**:
  ```
  phone(session code) PUT /me/level quiz on draft clip …-1 → 200 {"level":"A2","changed":null}
  phone(session code) PUT /me/level quiz on draft clip …-2 → 200 {"level":"B1","changed":"up"}
  phone settings → 200 {"level":"B2","changed":"set"}
  phone PUT /me/progress on draft clip → 200
  ```
- **Fix:**
  - In the quiz branch, load `_count: { quiz: true }` and `status`. Return 404 unless the clip is `published`. Store `total = clip quiz count` and reject or clamp `correct > count`, so eligibility comes from the server.
  - Refuse `/me/level` and `/me/progress` when the learner was resolved through `x-session-code`. For example, have `learner()` return `{ learner, via: 'device' | 'session' }`, or use a `tvOnly` guard that answers 403 when the header is present.
  - Add API tests for draft clip → 404, `total` ignored, and session code → 403.

### M2 — Quiz "correct" never shows the blue ring: the focus outline overrides it on the option just picked
- `packages/shared-ui/src/components/Focusable.tsx:49-55` (style order: `selected` ring at :52, then `focused` border at :53).
- `packages/shared-ui/src/screens/Quiz.tsx:84-90`.
- **Defect:** the correct-answer state is drawn as `selected` (interactive 3 px ring), and `focused` is applied after it with `borderColor: tokens.color.focus`. In the `correct` phase the correct option is always the focused one, because the learner just pressed Select on it. For the whole 600 ms auto-advance the ring is therefore the off-white focus outline, not the interactive blue. §8 and the non-negotiables say "Correct: blue ring + check"; only the check is blue on screen. The `revealed` path works, because focus moves to Continue. `quiz.test.tsx` passes only because the renderer never fires `onFocus` before the pick.
- **Scenario:** Quiz on TV, select the right option. The outline stays off-white with a blue check for 0.6 s, then advances. The "blue ring" never appears for a correct answer.
- **Fix:** let a semantic state win over focus while still showing focus physically. For example, give Focusable a `tone?: 'correct' | 'incorrect'` that keeps its border colour and draws focus as an extra outer ring (a wrapper border with the 3 px offset from the brief). Alternatively, in Quiz, render the correct/incorrect ring on an inner View so the Focusable's border stays the focus ring. Add a render test that calls `props.onFocus()` on the option, then `onPress()`, and asserts an interactive-coloured ring.

### M3 — Root's clip cache is never invalidated, so the Player plays stale native lines and highlights after "I speak" or the level changes
- `packages/shared-ui/src/app/Root.tsx:202-205` (PlayerRoute: `cached ? Promise.resolve(cached) : ep.clip(slug)`), `:219`.
- `Root.tsx:310-327` (SettingsRoute never clears `ctx.clips`).
- `Root.tsx:278-283` (level-up does not clear it either).
- **Defect:** `GET /clips/:slug` bakes in two values at fetch time:
  - the native line for `x-native`;
  - the highlight set filtered by `highlightFloor(learner.level)` (decision 0007 M5).

  `clips` is an app-lifetime Map. ClipRoute refetches on mount, but PlayerRoute (hero Watch, Continue → Watch, Summary "Watch again", launch intents) uses the cached entry without asking the server.
- **Scenario:**
  1. Open clip X (now cached with English native lines).
  2. Settings → "I speak" → Türkçe.
  3. Home hero Watch on X: the Player shows English native lines. The Explain chips and the Summary saved words follow the old level's highlight floor after a quiz level-up or a Settings level change.
- **Fix:** clear `ctx.clips` whenever `native`, `learning` or `level` changes (in the Settings/FirstRun/Quiz handlers, or an effect on `[learner.native, learner.level, learner.learning]`). Alternatively key the cache by `${slug}:${native}:${level}`. Optionally PlayerRoute can revalidate (`useResource(() => ep.clip(slug), [slug], cached)`) while rendering the cached copy.

### M4 — Words: changing the filter can unmount the focused row and leave no element focused (Vega and VoiceView)
- `packages/shared-ui/src/screens/Words.tsx:81-90` (`pref` computed once per mount; rows keyed by `savedWordId`).
- `Root.tsx:132` + `nav/stack.ts:109-114`: `routeKey` ignores the filter, so `replace(words(f))` keeps the same Words instance.
- **Defect:** ◄► replaces the route, but the RouteView key (`len:words`) is unchanged, so Words does not remount. `pref.current` stays as computed for the first list. When the focused row is absent from the new filter, its native view unmounts and no remaining row has `hasTVPreferredFocus`.
  - Fire OS leaves nothing focused until the next D-pad press.
  - Vega honours `hasTVPreferredFocus` on initial mount only (decision 0006 §5), and the surviving rows are not new mounts, so it cannot recover via the prop.
  - The announcement (`filterLabel`) is spoken, but VoiceView has no focused element to continue from.

  This conflicts with the plan's "exactly one preferred focus per mounted screen state".
- **Scenario:** Rail → Words (All), ▼ to a word due next week, press ► ("Due today"). That row disappears and focus is gone; the next ▼ jumps to whatever Android picks, and on Vega focus may stay lost.
- **Fix:** key the list container by filter (`<ScrollView key={filter}>`) and compute `pref` per filter, e.g. `useMemo(() => pickPreferred(initialFocus, ids, ids[0]), [filter])`, so the rows remount with one preferred row. Better still, prefer the last focused id when it is still in the new list. Add a render test: focus row X, switch to a filter without X, and assert exactly one row has `hasTVPreferredFocus`.

## Low

- **L1 — Home row titles name the new level over the old level's rows.**
  - Where: `Root.tsx:320-326` (Settings level) and `:282` (quiz level-up).
  - Defect: `memory.forget('home')` runs but `setCatalog(null)` does not. Home mounts with the cached catalog, and `homeRows(data, learner.level)` titles it with the new level ("Just right for you · about B1" over A2 clips) until the refetch lands.
  - Fix: `ctx.setCatalog(null)` on any level change, as is already done for a `learning` change.
- **L2 — Level-rule window mixes two clocks.**
  - Where: `learning.ts:31,36-39`.
  - Defect: `QuizAttempt.at` comes from the DB (`DEFAULT CURRENT_TIMESTAMP`), while `levelChangedAt = new Date()` comes from the API host. If the API clock lags the DB by more than the few ms between the two writes, the attempt that triggered the level-up has `at ≥ levelChangedAt`. It is counted again in the new window, and one more ≥ 90 % quiz moves up a second band.
  - Fix: take one `now` per request and write it both as `at` and as `levelChangedAt`, or filter `at > levelChangedAt` with both stamped from the same source.
- **L3 — `x-session-code` is a non-expiring bearer for the TV learner, and the merge put it on more routes.**
  - Where: `lib/learner.ts:12-20` with `routes/learning.ts`, `catalog.ts`, `clips.ts`, `iap.ts`.
  - Defect: the code now also reaches library, progress, level, and `/iap/verify`, which attaches a receipt to the TV learner. The code space is 32⁶ ≈ 1.07e9, there is no rate limit, and 404 `UNKNOWN_CODE` vs 200 is an oracle.
  - Fix: expire or rotate sessions (e.g. 24 h idle), rate-limit by IP on UNKNOWN_CODE, and, per M1, keep TV-only writes device-only.
- **L4 — `POST /me/words` emits to any room.**
  - Where: `apps/api/src/routes/me.ts:29-34`. Pre-existing; d4f1c48 touched this handler.
  - Defect: `sessionCode` in the body is never checked against `l`'s sessions, so `word:saved` (word, gloss, clip title) can be pushed into any room whose code is known.
  - Fix: `db.session.findFirst({ where: { code, learnerId: l.id } })` before emitting.
- **L5 — First run swallows a failed placement save.**
  - Where: `Root.tsx:143`.
  - Defect: the level is set locally and the `putLevel` failure is dropped. The TV then shows "about B1" for the session while the server keeps A2 (and the old `levelChangedAt`); the next boot silently reverts.
  - Fix: roll back on failure as SettingsRoute does, or retry once.
- **L6 — Content Launcher resume position is dropped.**
  - Where: `Root.tsx:114`.
  - Defect: `useLaunchIntents` passes `positionS`, but `onOpen: (slug) => …` discards it.
  - Fix: ignore it on purpose and use server progress (say so in a comment), or put it on the player route.
- **L7 — Pair button label does not state its purpose.**
  - Where: `screens/Pair.tsx:234`.
  - Defect: the aria-label is the bare text "Later" / "Continue", which does not meet CLAUDE.md "aria-label stating purpose".
  - Fix: e.g. `Pair later and go on` / `Continue to Lingo`; add `strings.pair.laterLabel` / `continueLabel`.
- **L8 — Words row label promises playback that cannot happen.**
  - Where: `strings.ts:32` + `Words.tsx:90`.
  - Defect: the row label always ends "Select to play the line", including words whose `manifestUrl` is null (a "not available" line is shown instead).
  - Fix: drop the suffix when `manifestUrl === null`.
- **L9 — Collapsed rail letters are ambiguous.**
  - Where: `components/Rail.tsx:41`.
  - Defect: Watch and Words both collapse to "W". The aria-labels are fine; this is visual only.
  - Fix: icons, or a distinct glyph per item.
- **L10 — Small copy and state nits:**
  - (a) Summary/Quiz show `strings.common.error` ("on our side") for a client cache miss (`Root.tsx:260,277`).

  - (c) The focus ring has no 3 px offset as the brief specifies (`Focusable.tsx:53`, `margin: -width`). Pre-existing, not introduced here.

## What holds up (verified)

- **§8 screens and states**
  - Home: skeleton hero + 2 rows with a hidden live region; offline StateMessage with `announceOnMount`; server error; stale data kept; empty → "Open Settings"; empty Continue hidden through `homeRows`.
  - Clip: skeleton; preparing with a 30 s poll that stops on unmount; notFound; Retry + Back.
  - Words: 5 skeleton rows; a separate empty message per filter; offline spoken.
  - Quiz: empty state.
  - Summary: no-words line.
  - Root: boot offline with Retry, spoken.
- **Focus memory:** remount plus `hasTVPreferredFocus` from a per-route-key map. One preferred element per state on Home, Clip, Settings and Quiz. Rail `nextFocusRight` and first-card/hero `nextFocusLeft` go through `findNodeHandle`. Navigation is a hand-rolled stack with one BackHandler registered first (empty deps). No RN `<Modal>`; no ✓ glyph (`Check`).
- **Tokens and labels:** colours only from tokens. Focusables carry purpose labels (apart from L7).
- **Level rule** (`lib/levelRule.ts`): attempts are eligible at ≥ 5 items with clip ≥ learner level; ineligible ones neither count nor break a run; consecutive retakes collapse; two newest on distinct clips ≥ 90 % → up one band; B2 stays B2; never down. The client never posts phone results (sockets.ts comment; no `putLevel` in apps/phone). See M1 for server-side enforcement.
- **Catalog rows:** continue (unfinished, newest progress), justRight (unfinished first), harder (`NEXT`, empty for B2), fresh (7 days, max 10), drafts excluded, query overrides validated. The M5 highlight floor (`highlightFloor`, BANDS moved to contracts) is applied before `wordsYoullMeet` (distinct lemmas, ≤ 8).
- **Copy:** quiz copy is "Right: X" / "The answer: X" plus the native line for meaning items; no wrong/failed (lint green). Level labels say "about" everywhere except the space-limited chip, as Open question 4 allows.
- **Placement:** content verbatim; ≤ 42 chars per line; band mean ≥ 0.75 with stop at the first failing band; Skip → A2; Back walks panels; Back on the first panel is unhandled, so the OS exits.
- **Plus:** reachable from the rail (`onRail('plus')`), Settings (`open plus`), Clip (`onPlus`) and Player (`onPlus`). Challenge is gated twice (`Clip` on `learner.plus`; `PlayerRoute` passes `challenge && learner.plus`). 0.75× is gated in the player machine, SettingsSheet and Explain. `learner.plus` comes from `entitled()` on both GET and PUT /me. Startup restore runs once, only in iap mode with a store.
- **API ownership:** progress, level and library are scoped to `l.id`; `/me/reviews` 404s another learner's word. Within one learner id this holds; see H1 and M1 for the gaps.
- **Merge:** `lib/learnerLookup.ts` is gone with no remaining imports (typecheck green). `iap.ts` and the TV routes use `learner(req)`. The free-tier limit and `/iap/status` share `savesSince`.
