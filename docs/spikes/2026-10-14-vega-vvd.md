# Spike — Lingo on the Vega Virtual Device (LING-008, "simulator shot, no video")

**Date:** 2026-10-14 · **Machine:** the human's Mac, macOS 26.2 (25C56), Apple Silicon, Node 22.19, npm 10.9.3, Homebrew 7.0.6
**Outcome:** Lingo runs on the Vega Virtual Device (SDK 0.24.12112, Vega CLI 1.4.4). Home, the rail, the Clip screen and Words render from
shared-ui with live catalog data from the host API; the Player shows the playback-off message as designed (caps.playback false, KIT-010).
Screenshots and a 5–10 s recording are in this directory. Two apps/vega fixes were needed (manifest, Metro); nine friction logs (§6).

## 3. Observations for the checklist (rows in apps/vega/README.md)

- Home renders in Noto Sans / Manrope on the dark ground; focus is outline + scale; Back works (Player → Clip → Home).
- LEFT from the hero enters the rail at the geometrically nearest item, not the current one: **Settings** from the Watch button at rest
  (y≈430 vs 448), **Review** when the hero is scrolled up. DOWN at the rail's last item bounces focus back into the content. The rail
  has no explicit entry target for LEFT; compare with Fire OS before changing shared-ui.
- After UP from the Continue row the hero stays scrolled so the title shows as "X)" (scroll offset not reset when focus returns to the hero buttons).
- On this fresh device id, Home shows the clip under "Continue" at 0:00 after one Watch (known low B-L3).
- On one relaunch the app came up on the Player's playback-off screen for the last clip (stack Home → Clip → Player), not on Home; not investigated (resume or a repeated launch message from `vega device launch-app`).
- Rows 7 (Pair/QR), 9 (Quiz), 10 (S2 questions) not run in this spike.

## 4. Commands for the human (the VVD is left running with the GUI; `vega` is `~/vega/bin/vega`)

```sh
export PATH="$HOME/vega/bin:$PATH" KEPLER_SDK_PATH="$HOME/vega/sdk/vega-sdk/main/0.24.12112"
cd ~/hackathon/lingo/apps/vega

# simulator (GUI; the window is "Vega Virtual Device", 960×568 on screen, 1920×1080 inside)
vega virtual-device start --display-res=1920,1080          # or --no-gui; stop with: vega virtual-device stop
vega device start-port-forwarding --device VirtualDevice -p 4000 --forward false   # after every VVD start; API must run on :4000
vega run-app build/aarch64-release/vega_aarch64.vpkg dev.moizp.lingo.main -d VirtualDevice

# remote keys (no developer mode needed)
vega exec vda -s emulator-5554 shell "inputd-cli button_press KEY_LEFT"    # KEY_RIGHT KEY_UP KEY_DOWN KEY_ENTER KEY_BACK; add 'long' for a long press

# screenshot (host side, 1920×1080 PNG) — the device-side tools do not work on the VVD
T=$(cat ~/.emulator_console_auth_token); printf "auth $T\r\nscreenrecord screenshot ~/hackathon/lingo/docs/spikes\r\nquit\r\n" | nc -w 8 localhost 5554

# 5–10 s recording for the submission video (WebM VP9 1920×1080, then MP4 for the editor)
printf "auth $T\r\nscreenrecord start ~/Desktop/lingo-vega.webm\r\nquit\r\n" | nc -w 8 localhost 5554
#   … press keys (above) or use the window with the keyboard: Esc=Back, F1=Home, F2=Menu, arrows, Enter …
printf "auth $T\r\nscreenrecord stop\r\nquit\r\n" | nc -w 8 localhost 5554
ffmpeg -i ~/Desktop/lingo-vega.webm -c:v libx264 -pix_fmt yuv420p -crf 20 -an ~/Desktop/lingo-vega.mp4
#   alternative: macOS Shift-Cmd-5 → Record Selected Portion over the VVD window

# logs
vega exec vda -s emulator-5554 shell "loggingctl log -f -o short_precise" | grep dev.moizp.lingo
vega device get-log-info --device VirtualDevice; vega device copy-logs --device VirtualDevice --artifact SYSTEM_TOMBSTONE/acr --directory /tmp/vvd   # JS crashes land here
```
