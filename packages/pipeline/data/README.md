# data/
- freq-de.txt, freq-en.txt — top 20 000 lemmas, most frequent first, rank = line number. Derived from hermitdave/FrequencyWords (OpenSubtitles 2018, content CC BY-SA 4.0, https://github.com/hermitdave/FrequencyWords) lemmatized with simplemma 2.0.0 (MIT). Regenerate: `pnpm --filter @lingo/pipeline build:freq` (needs network and a Python venv with simplemma==2.0.0). Sidecar `freq-*.meta.json` records source sha256, versions and how many name forms were stripped. These derived lists remain CC BY-SA 4.0.
  - The source lists are lowercase, so for German every form is looked up capitalised as well: a form whose capitalised lookup is a different known lemma (haus → hausen / Haus, hat → haben / Hat) credits both, except that the lowercase lemma must be attested by the list's other forms (≥ 1 % of the form's count — bitten and danken pass, hausen/tagen/zimmern do not). See `creditLemmas` in scripts/build-freq.ts. A capitalised lookup that comes back as simplemma's ambiguity marker (`Sich → er|es|sie`) is ignored, so `sich` keeps its own count (rank 51; docs/decisions/0008 decision 10).
  - Names are stripped before ranking (a listed name never has a rank), so the de fallback in names.ts — capitalised, uninflected, unranked → name — can fire.
- names-de.txt, names-en.txt — seeded from the same CC BY-SA 4.0 FrequencyWords lists (so they stay CC BY-SA 4.0; attributed in docs/aws.md). First names, surnames and places (people, cities, countries, brands, holidays) never highlighted: matched verbatim by names.ts and stripped from freq-*.txt at build time. One per line, sorted, hand-maintained; grown by the spot check. Seed rule (2026-09-18): a lowercase form of the raw list whose simplemma lemma is its own capitalised form in BOTH the German and the English dictionary (`lemmatize(w,'de') === lemmatize(w,'en') === Cap(w)`, e.g. anna → Anna in both, whereas frau → Frau only in de and hotel → Hotel/hotel) is a proper noun in both languages; that seed was eyeballed and common nouns, months, weekdays, demonyms, languages and foods removed (Halle, Roman, August, Berliner, Pilates…), then names the English dictionary knows as words (Bob, Bill, Frank, Max, Grace, Green…) were added by hand from the top 8 000 — for de only where the word is English vocabulary (Green, Hunter, Bill stay in freq-en.txt).
  - Seed 2 (2026-10-02, docs/decisions/0008 decision 8): `pnpm --filter @lingo/pipeline build:names` merges the spot-check hand additions (`HAND` in scripts/build-names.ts) and every single-token **region and continent** name (ISO 3166-1 + UN M49) that `Intl.DisplayNames` (Node ICU / Unicode CLDR) gives in that language. Language names and demonyms (English, Polish, Englisch, Französisch) are never seeded: they are vocabulary, and because build:freq strips names case-insensitively a seeded `Polish` would also unrank `polish`. `EXCLUDE` drops region labels that are ordinary words (en Jersey, Chad, Guinea, Turkey, China, Jordan, Georgia; de Jersey — Island, Georgien, Polen are only names in German); it stops the seed and does not remove entries that predate it (China, Jordan, Georgia in names-en; Jersey in names-de). A label is also skipped when simplemma knows its lowercase form and it ranks below 1 000. Deterministic and idempotent; run `build:freq` afterwards so the new names are stripped from the ranks. The Wikidata given-name seed of the plan is a follow-up.
- .cache/ — downloaded sources, gitignored.

Try it without AWS: `pnpm --filter @lingo/pipeline cli prepare --clip demo-de --source s3://unused --lang de --native en --fixture --no-publish` (and `--clip demo-en --lang en --native de`) writes `work/<slug>/{clip.json,<lang>.vtt,native-<native>.vtt}` from the committed Transcribe fixtures.

Manual correction (docs/decisions/0007): the quality gate on the target track stays hard, but before it fails `prepare` writes `work/<slug>/<lang>.vtt` (what the segmenter produced), `gate.json` (every finding with its cue text and time span, plus the dropped cues) and, when the segmenter dropped a short back-channel or interjection, `dropped.vtt`; the error ends with the command to run next. Open `<lang>.vtt` next to `work/<slug>/mezz.mp4` in any subtitle editor, condense, retime, split or merge the cues (a line break you write is kept; `-` at the start of both lines marks a two-speaker cue), copy a block from `dropped.vtt` back in to restore a dropped cue, save, and re-run the same command with `--cues work/<slug>/<lang>.vtt`. That run skips Transcribe and segmentation, reuses `mezz.mp4` (ffprobe only), and runs the same gate. Two things to know about a `--cues` run: it never writes or deletes `dropped.vtt`, so the file from the first run stays in place (and its blocks stay restorable) even after you restored them; and every line in the edited VTT that starts with `-` is read as a speaker line (the hyphen is stripped from the tokens and the next word counts as sentence-initial), so do not start an ordinary line with a hyphen. Two-speaker cues to look at without AWS: `pnpm --filter @lingo/pipeline cli prepare --clip overlap-de --source s3://unused --lang de --native en --fixture overlap --no-publish` (12 cues, 3 dropped).

Re-measure after a pipeline change (docs/decisions/0008 decision 12): `prepare --reuse` takes `work/<slug>/transcript.json` and `mezz.mp4` from an earlier run when they exist (no download, no ffmpeg, no Transcribe; Translate and Bedrock still run unless `--no-ai`). Every step logs its elapsed time (`[12.3 s] translated (en)`), and every `clip.json` warning is printed as `warning: …`. Offline numbers for the two real fixtures (test/fixtures/real/): `pnpm --filter @lingo/pipeline stats` (before = `test/fixtures/real/baseline-stats.json`, after = the current pipeline); `pnpm --filter @lingo/pipeline stats work/<slug>/clip.json` for any prepared clip.
